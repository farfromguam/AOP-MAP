  • All four read the same source — the selected feature's real fields (Name/Description/Kind editable in the grid; Status/Source/Caveat from the data) — and all four update live as you edit.
  • Empty-state is honest — A/B hide missing meta exactly as the map popup does; C calls out every blank so you know what's still owed; D shows a soft "No description yet."
  • A vs C is the real fork — do you want the preview to look like the published result (A/B) or like a fill-in checklist (C)? They're not exclusive; A could gain a small "blanks" hint.

My recommendation

A — the faithful popup card. You asked to see the feature's text "as it will be shown when active on the map," and A is that — the exact popup, same styling, updating as you type. No guessing, no translation. It's compact, so the map keeps most of the right column.

B (phone frame) is the same thing with more truth-in-context if you like seeing it on a device; C (labeled fields) is worth keeping as a toggle for filling blanks. D only makes sense if you also want to redesign the real map popup — flag that and it's a separate, bigger job.
