Drawn POI CRUD — variant compare

Tree shape is fixed: Drawn POI → POI / Footprint / Line → named item. The four variants differ only in where the terminal-node editor lives and how much room it gets. Same fake data in every frame (10 features, Big tent pre-selected) so the comparison is fair.
Variant axis 1: editor placement (inline / split / over-panel / pinned) Variant axis 2: panel width (380 px / 560 px) Constant: tree shape, fake data, palette

1 Inline accordion

Click a leaf → it expands in place, pushing siblings below it down. Click ✕ to collapse back to a row.
Pros
Cons
No new surface; everything inside the existing section.
Long pages when expanded; surrounding leaves get pushed off-screen.
Reads as direct edit of the row you clicked.
Editor field room is constrained to 380 px panel width.
Open website/poi_crud_v1_accordion.html

2 Master / detail (wider panel)

Right panel widens to ~560 px while Map editor is open. Tree on the left, editor pane on the right; both always visible.
Pros
Cons
Tree never disappears; selection always anchored.
Wider panel eats map. Only justifiable while Map editor is open.
Editor pane sized for real form fields.
Tree column compresses leaf row UI (no inline tag/move buttons).
Open website/poi_crud_v2_master_detail.html

3 Slide-over drawer

Tree stays narrow. Click a leaf → drawer slides over the right panel with the full editor; ‹ Back returns to the tree.
Pros
Cons
Roomiest editor — full panel width. Future-fields fit (source register).
Tree hidden while editing; quick context-switch between leaves is slower.
Doesn't widen the panel, doesn't compress the tree.
Extra UI surface to maintain (open/close, back-stack, escape key).
Open website/poi_crud_v3_drawer.html

4 Pinned editor card

Tree scrolls in a region inside the section. Selected leaf's compact editor card is pinned at the bottom — always visible. ⛶ Expand goes to a fuller form.
Pros
Cons
See tree and selection at the same time without widening.
Editor card is small; multi-line notes feel cramped.
Switching leaves is one click; no open/close ceremony.
Two scroll regions (tree + section) inside the panel.
Open website/poi_crud_v4_pinned.html

What every variant changes vs. today

  • Tree (new): flat list → Drawn POI → POI / Footprint / Line → named feature. Geometry kind is visible at the root; category becomes a leaf chip.
  • Create surface: the three draw buttons stay; category <select> demoted to "default for next draw" and made narrower.
  • Terminal editor: name, category (now mutable post-create), tag, ★ visitor surface, ☑ on-map, notes (new field, persists in properties.notes), geometry summary, action row (Fly, Move, Duplicate, Copy GeoJSON, Delete).
  • Click-popup retires: map-click on a drawn POI selects the leaf in the tree + opens its editor — no separate inline popup.
  • Open follow-up: source-register fields (source, confidence, permission, publishable, last-checked) plug in to the same editor surface once the Sprint 03 loop lands.
