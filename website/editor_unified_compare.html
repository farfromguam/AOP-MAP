Editor unified — variant compare

Goal: the right-rail Map editor section becomes the single home for every author + reference layer the user can touch. The current 5-toggle strip (showEventSchedule, showTrailheads, showVisitorContext, showBrandLogos, showEditorPois) goes away. The five buckets in the prior pass (Point / Line / Polygon / Image / Callout) collapse to three: Point · Line · Polygon.

What "everything in one place" means here: brand logos render as icon images but they are geometrically Points — they live under Point. Visitor context renders as labeled callouts but they are geometrically Polygons — they live under Polygon. Event-schedule POIs are just regular POIs with a #tag that the schedule binds against — they live under Point with the rest of the drawn POIs, no separate group.

The four variants below differ only in how each bucket organizes its mixed-source contents (drawn / trailheads / brand / visitor) and where the layer-level on/off lives now that the strip is gone.

Variant axis 1: source organization (sub-groups / chips / focused / dots) Variant axis 2: layer-level on/off location (sub-group head / filter chips / sub-group head / Source-Derived-External) Constant: three buckets, same data, same ★ Visitor list, same create footer

1 Sub-grouped buckets

Each bucket contains source sub-groups (Drawn / Trailheads / Brand / Visitor) with their own chevron + bulk visibility. Sub-group bulk = layer-level toggle.
Pros
Cons
Two-level grouping reads cleanly: kind first, source second.
More vertical space — every source gets its own header even with 1 row.
Layer-level on/off lives where the data lives. No floating strip.
Drawing a new Point lands it deep in a sub-group, not at the bucket top.

2 Source chips on each row

No sub-groups. Each row carries a colored source chip. Filter chips above the buckets mute or hide whole sources — they replace the 5-toggle strip.
Pros
Cons
Flattest tree — fewest clicks to reach any row.
More visual noise per row (chip + name + actions).
Filter chips are scannable; one click hides a whole source.
No sub-group header means you can't bulk-act on "all brand logos" by tapping a head.

3 Focused (Drawn open, refs collapsed)

Same shape as V1 but only the Drawn sub-group is open by default. Trailheads / Brand / Visitor are one click away with their counts visible on the head.
Pros
Cons
Edit-focused default; reference clutter recedes.
Reference layers feel "hidden behind a click" — easy to forget they exist.
No new affordances over V1 — just a default-state opinion.
User who wants to ★ a trailhead needs to expand first; one extra click.

4 Minimal dots (no sub-groups, no chips)

Three buckets, flat rows. Source is a small colored dot at the row start; a one-line legend explains the palette. Layer-level on/off moves out to Source / Derived / External reference where data toggles live anyway.
Pros
Cons
Most compact; rows read like a sortable list.
Layer toggles split across sections — "where do I hide brand logos?" needs an answer.
Editor section stays slim — no nested heads, no filter strip.
Source dot is subtler than a chip — easy to skim past.

What every variant changes vs. today

  • Five buckets become three. Image and Callout merge into Point and Polygon respectively. Render style (icon-image, callout-label) is a property of the row, not a top-level axis.
  • 5-toggle strip is gone. showEventSchedule, showTrailheads, showVisitorContext, showBrandLogos, showEditorPois stop being floating layer switches above the tree. Their function moves into the tree (V1 / V2 / V3) or into the existing data-layer sections (V4).
  • Event-schedule POIs are regular drawn POIs. No separate row group; the #tag on the POI is the binding to the schedule entry.
  • Drawn POIs stay split across buckets. A Point lands under Point, a Polygon under Polygon, a Line under Line — driven by feature.geometry.type, same as today.
  • ★ Visitor list stays at the top of the editor. Live mirror of every highlighted feature across the tree; same source chip on each row.
  • Create footer is unchanged. Category select + Place / Draw / Trace + Export / Clear / status / help at the bottom of the section.

Pick lens

  • If you usually focus on authoring and only check refs occasionally: V3 (focused) reads best — drawn rows are the default surface.
  • If you treat all rows as roughly equal and want to bulk-toggle by source: V1 (sub-grouped) gives that affordance natively.
  • If the curation question is "where is this row from" more than "what kind of thing is it": V2 (chips) puts source on the row.
  • If you want the editor as compact as possible and don't mind moving layer toggles out: V4 (dots) is the smallest visual footprint.
