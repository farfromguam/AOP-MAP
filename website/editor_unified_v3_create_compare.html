V3 — per-bucket create button (three placements)

Direction: each bucket carries its own create affordance. The footer's three draw buttons (Place POI / Draw footprint / Trace line) go away — their job moves into the tree. The three variants differ in where the + sits and whether category lives next to it.

Constant: Terra Draw (vendored at website/vendor/terra-draw.umd.js) stays the input primitive. Clicking + calls setDrawMode('point' | 'polygon' | 'linestring'), the user clicks on the map, and the finished geometry routes into editorPois with the chosen category. Polygon shown active in every variant.

Axis 1: + placement (bucket head / sub-group head / inline create row) Axis 2: category location (footer / footer / per-bucket inline) Axis 3: what's still in the footer

a Bucket-head +

A green + button on every Point / Line / Polygon bucket head. One click sets Terra Draw's mode. Active state echoes on the button (rust fill).
Pros
Cons
Fewest new affordances — one button per bucket.
Category still lives in the footer; eye has to ping-pong on first draw.
Always-visible without expanding anything.
Bucket head gets a bit busy: chev, bulk-vis, label, count, +.
Open website/editor_unified_v3a_buckethead.html

b Sub-group-head + (Drawn only)

The + lives on the Drawn POIs sub-group head only. Trailheads / Brand / Visitor sub-groups have no + — you can't author them from this UI.
Pros
Cons
Most semantically honest — you create a Drawn POI, not a "Point."
Hidden when Drawn sub-group is collapsed (default-open in V3, but still).
Bucket head stays clean.
If a future sub-group ever becomes author-able (e.g. brand logos via add-image), each one needs its own +.
Open website/editor_unified_v3b_subgrouphead.html

c Inline create row

Bucket-head + expands an inline create row right below the head: bucket-scoped category select + the matching primary action (Place / Draw / Trace). Footer shrinks to Export / Clear / status / help.
Pros
Cons
Category sits next to the create action — no eye ping-pong.
Most new DOM — an open/close state per bucket + a category select per bucket.
Each bucket can offer the categories that actually fit it (Polygon ≠ Point list).
Slight redundancy if user has the same category mental model across buckets.
Open website/editor_unified_v3c_inline.html

What every variant shares

  • Footer loses the three draw buttons. Place / Draw / Trace move up into the buckets.
  • Terra Draw wiring is unchanged. Same modes (point, polygon, linestring), same draw.on('finish', ...) handler in our JS, same lift-and-store into editorPois.
  • Active state echoes on the + button. Rust-filled while drawing; reverts on finish or Esc.
  • Reference sub-groups get no +. Trailheads / Brand / Visitor are not author-able from this section.
  • Visitor list bucket gets no +. It's a virtual mirror, not a place to create features.
