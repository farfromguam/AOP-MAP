Data editor + map — where should the map live?

The shipped data_editor.html is a blind spreadsheet: you edit a Lat/Lng with no way to see where the point lands. One direction, four placements. Every take is the same real editor (same round-trip-safe cells, same per-file localStorage['aop_dataedit::<file>'] autosave) with one map added over the same TNMap satellite imagery the public viewer uses, and two-way selection sync: click a row's # to fly the map there, edit a Lat/Lng and watch the marker move on the aerial, click a map feature to jump to its row. They differ only in where the map sits and when it's visible. The frames below are live — drive them. Pick the placement and I'll fold it into data_editor.html and bump the shell VERSION.

V1Side dock — map pinned right

RecommendedGrid left (~56%), map fixed on the right (~44%). Both always visible — the literal "map viewer in the right sidebar." Best on a laptop where you're working a file top-to-bottom and want each edit confirmed against the imagery without a click.

  • What's identical in all four — the editor itself: Name · Tag · Kind · Lat · Lng · Description, inline edit, ＋ Add point, delete, ⤓ Export, ↺ Reset, round-trip-safe (unshown props + non-point geometry preserved), per-file autosave + close-flush. The map is purely additive.
  • What's identical about the map — TNMap satellite (with a Street toggle), all geometry types drawn (points, the recorded trail lines, parcel polygons), selected feature highlighted in rust, fly-to on select, and a live marker move when you edit Lat/Lng. Lat/Lng stay read-only for lines/polygons ("edited on the map, not here").
  • The one real fork — is the map always there (V1/V3) or summoned (V2 collapse / V4 slide-in)? Always-there wins for desk work ("see it while I type"); summoned wins for a phone in the field where screen is scarce. V1 vs V3 is just which pane leads.
  • Offline note — the basemap tiles need a connection; the editing + autosave do not. At a desk this is moot. For true offline field use the imagery would need precaching (a later step), but the grid still edits fine with a blank basemap.

My recommendation

V1 — side dock (map pinned right). It's literally what you asked for — "a map viewer in the right sidebar" — and it gives the highest payoff for the actual job: making informed edit decisions. With the map always beside the grid, every Lat/Lng you touch is confirmed against the satellite in real time, no click required. It reuses the public viewer's imagery so what you see here is what the map will show.

Keep V2 (bottom drawer) in your pocket for the phone-in-the-field case — it's the same engine, just stacked. If you'd rather the editor stay visually unchanged until you need the map, V4 (overlay) is the smallest diff.
