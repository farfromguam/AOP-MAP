# Research Flow

TL;DR: Produce one focused research brief. Evidence in, recommendation out.

#flow #research #brief

-----

Use this when the project needs to understand a source, decision, tool, method, or risk before acting.

## Inputs

- Research question.
- Scope boundary: quick, standard, or deep.
- Known source paths or URLs.
- What decision the research should support.

## Work

Restate the question.

Define in/out scope.

Start with existing local docs.

Capture facts with source links.

Separate authoritative, observational, commercial, and anecdotal sources.

Compare options on risk, effort, permission, confidence, and usefulness.

Recommend one next action.

List open questions and the evidence that would close each one.

## Output

Write one markdown brief in `research/` or `output/`.

Default sections:

- Question
- Scope
- Current state
- Sources
- Options
- Recommendation
- Open questions
- Next actions

Do not turn a research brief into an implementation card unless the user asks.
