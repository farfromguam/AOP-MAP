## Definition — what a "shadow attribute" is

A value or behavior that drives what the user **sees or edits** but is **not a
first-class attribute on the feature in the Common Minimum Feature Schema**.
Instead it is smuggled in by one of:

1. **Runtime sidecar join** — the display value is joined in at render time from a
   *separate* file (e.g. trail name from `aop_trail_catalog.json` by `trail_number`;
   blurbs from `aop_poi_index.json`). The attribute is not on the feature.
2. **Render-time derivation** — computed in a renderer/label/fallback
   (`'Trail ' + name`, `?? blurb`, `|| 'Trail'`), durable nowhere.
3. **localStorage-as-truth** — curation/state that drives the published view but
   lives only in a browser `aop_*_v1` store (stars/`highlight`, tags, overrides,
   `positioned_features`). Violates **C3** (`curation is data, not browser state`).
4. **Per-layer edge-case dispatch** — identity/behavior resolved by hidden
   special-casing: cemetery `:marker` vs `:parcel`, trail `sfwda-<n>` load-index
   (≠ trail number), visitor `-N` synthetic index, any `layerKey === '…'` branch.
   Violates **C1** (`behavior lives in the spec, never at the call site`).
5. **MVP shortcut / half-converged schema** — a feature "works" only via a crutch
   that bypasses the canonical schema: a canonical field left blank or set to a
   stand-in (trail `name = "1"`), a crosswalk row never populated, a `_schema.json`
   gap.

**The tell:** the same concept carries a *different value or name across two
surfaces* (left list vs right panel, served file vs DB, panel's own fetch vs the
host's load-time stamp) — because the truth is not one apparent field.

## The migration target — the CMFS (do not re-invent)

`research/common_feature_schema.md` is the contract. Every cut shadow attribute is
re-homed onto a canonical field:

- **Tier 1 — identity (always editable):** `id` · `name` · `description` · `kind`.
- **Tier 2 — provenance (`source_register.md`):** `source` · `confidence` ·
  `permission` · `status` · `last_checked`.
- **Tier 3 — facets (only where the `kind` needs them):** `difficulty`, `category`, …

The crosswalk (logical field ← physical keys) and the per-layer provenance live in
`website/data/_schema.json`; the re-bake is `mvp/scripts/rebake_canonical.py`
(reads pristine `website/data/raw/`, additive). The canonical re-bake **shipped
2026-06-04 but is incomplete** — the Launchpad case proves canonical fields are
still blank / stand-in on at least the trail network. This card is the audit that
finds *how* incomplete, everywhere, and finishes the convergence.

## Method — the seal-team audit (running 2026-06-09)

A fan-out of read-only audit agents, one per **lens**, each producing structured
findings; then a synthesis pass that dedups, maps each finding to its CMFS target,
ranks severity, and names coverage gaps. Lenses:

1. Sidecar joins (runtime joins supplying display values)
2. Render-time derived display (label/row/fallback computation)
3. localStorage-as-truth curation (C3)
4. Per-layer edge-case identity dispatch (C1)
5. MVP shortcut / half-converged canonical fields (`_schema.json` + re-bake gaps)
6. Identity forks (same feature, different key/name across surfaces — spike-audit F6)
7. Bake/data drift (served carries keys not in DB; DB ≠ served ≠ panel — F4/F5)
8. Data-file schema variance (physical keys still off-canonical per the CMFS crosswalk)

Each finding: `{name, title, type, locations[file:line], evidence, drives,
contract_violated, target_canonical, severity}`.

## Guardrails (inherited — non-negotiable)

- **C5 — no limiting code.** The migration is **additive**: a crosswalk/re-bake
  that *adds* canonical fields and reads through them; it never rejects, drops, or
  validates a feature whose keys don't match. Unmapped keys fall through. Surface
  integrity gaps as findings, never as row-dropping filters.
  **Binding (Mason fold 2026-06-09):** every controlled-vocabulary target below
  (`kind`, `confidence`, `status`, `intensity_class`) is a **display mapping with a
  safe fallback** — map the known values, pass an out-of-vocab value through as its
  own label (mirror `rebake_canonical.py` `_PUB_KIND.get(layer, layer)`); **never** a
  reject, drop, coerce-to-blank, or throw. Note `source_register.md` defines *required
  fields*, not a closed value-enum — "enums" in a target line means a relabel, not a gate.
- **C1/C6 — converge, don't multiply.** Re-home shadows into the ONE registry spec
  + the ONE renderer + the ONE schema. Do not add a second catalog loader, a
  second list engine, a class hierarchy, or a parallel editor surface.
- **C3 — curation is baked data.** Stars/tags/overrides become feature attributes
  that travel store-of-record → bake → served, not localStorage truth.
- **Extend the existing audit, don't re-derive it.** Build on
  `output/council/spike_code_dbfirst_audit_20260608.md` (F1–F9) and coordinate with
  `06_going_gold/gold_migration.md` slice 6 (HELD DB doors / identity-fork collapse)
  — findings that belong to gold slice 6 are tagged, not re-carded.

### Synthesis (the fleet's plain-voice verdict)

The shadow-attribute problem is pervasive and concentrated: nearly every user-visible identity value (name, description, kind, id, provenance) on the editable reference layers is NOT a first-class served attribute — it is reconstructed at render time, joined from an off-schema sidecar, replayed from a per-browser localStorage diff, or left as a number/address stand-in by the re-bake. The single worst offender is the TRAIL: one feature (trail #1) shows four different names across four surfaces — "Launchpad" (left list, joined from aop_trail_catalog.json), "Trail 1" (right panel, from raw name="1"), "1" (map label), and is unsearchable as "Launchpad" — and carries four different identities (served id sfwda-16, name "1", row-id n:1, catalog "Launchpad"). I verified: 87/120 trails have a numeric canonical name, 120/120 have null description, and the catalog/poi_index sidecars are NOT registered in _schema.json's crosswalk (so the re-bake can never converge them). The second tier of offenders: BUILDINGS (canonical name is the street address; "Pavilion"/"Front Office" live only in facility_name + a poi_index blurb; status field holds the facility role "facility" not a publish state), CEMETERIES (every site is a parcel+marker twin sharing one non-unique id, disambiguated by an off-canonical geom_role), and the EVENT overlay (two divergent render-time resolvers, coordinate-less anchors positioned from a localStorage #tag binding). Cross-cutting it all are three structural roots, each verified: (1) localStorage-as-truth — the published reference view is the per-browser aop_panel_overrides_v1 / aop_positioned_features_v1 diff replayed at boot, and the same name edit forks to two stores with opposite bake fate depending on which surface made it; (2) the served publish.geojson is NOT reproducible from the live DB (carries retired `blurb`, ids 1-6 disjoint from DB serials 139-201) and FIVE files have two competing writers (DB export vs rebake-from-raw); (3) the re-bake left canonical name/description/difficulty as stand-ins or blanks and the crosswalk is missing the two sidecars + a Tier3 facet block. The fix is uniform: fold the sidecars into core.features, bake real canonical name/description/id, normalize provenance to the source_register vocabulary, give every surface one read field and one write-through-one-DB-door path. Note: the mvp/ scripts and live DB are at the parent dir (../mvp), not in this website/ checkout; bake-drift findings were verified by the originating agent against the running DB and I confirmed the data-side artifacts (publish.geojson shape, _schema.json gaps, rebake CONFIG) directly.
